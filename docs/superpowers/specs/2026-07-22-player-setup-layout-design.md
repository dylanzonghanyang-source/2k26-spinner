# 球员生成设定区布局设计

日期：2026-07-22

## 目标

提高球员生成设定区的信息密度和操作层级，减少姓名、年龄与成长设定对横向空间的无效占用，同时保留现有生成规则和移动端四步流程。

## 范围

本次只调整 `RookieBuilder` 的球员设定区以及与它直接相关的球队球员区头部：

- 球员身份、主次位置、成长设定、身体设定和底部操作区。
- 设定确认后的折叠摘要与重新编辑入口。
- 球员生成进度从设定区迁移到球队球员区。
- 名、姓独立输入及随机生成所需的数据状态和姓名生成接口。
- 新秀年龄的整数输入和校验。
- 新秀模式与巅峰模式在上述布局中的对应状态。

以下内容不在本次范围内：

- 转盘、球队抽取算法、球员列表、属性槽、结果面板及球员能力计算规则。
- 位置权重、非常规位置衰减、成长公式和身体参数生成规则。
- 新的功能入口、动画或第三方依赖。

## 设计原则

1. 控件宽度由信息量决定，不让短数字或短文本占满整列。
2. 主次位置是两个独立选择，不在同一组选项中混合表达。
3. 编辑设定、确认设定和生成进度属于不同阶段，应显示在各自所属区域。
4. 桌面端优先提高扫描效率；窄屏保持可点击尺寸和现有四步向导。

## 编辑态布局

设定面板由四个区域组成：上部身份与成长设定、身体设定、状态与操作底栏。桌面端使用紧凑横向布局；控件不随容器无限拉伸。

### 球员身份

- 第一行依次放置“名”“姓”“年龄”。
- 名输入组约 170 px，姓输入组约 195 px，年龄约 96 px；组间距约 10 px。
- 名和姓各自包含一个文本输入框和一个独立随机按钮。随机名只替换名，随机姓只替换姓，不重置即战力或其他设定。
- 输入框分别显示 `First name` 和 `Last name` 辅助标签，允许用户直接编辑；两个字段各自限制为最多 24 个字符。
- 新秀年龄使用数字输入框，接受 18 至 23 的整数，步进为 1。输入期间允许暂时为空；失焦或按 Enter 时提交，空值或非数字恢复上一个有效值，带小数或越界值取最接近的范围内整数。
- 巅峰模式的年龄固定为 28，只读显示，不提供步进或编辑能力。

### 位置选择

- 第二行并列显示“主位置”和“次要位置”，每组都是 PG、SG、SF、PF、C 五段式选择器。
- 两组选中项都使用相同的深色底和白色文字，避免颜色暗示两套不同语义。
- 当前主位置在次要位置选择器中禁用，且不能被选择。
- 未选中的常规与非常规次要位置都使用中性样式，不预先用红色制造视觉噪声。
- 只有用户实际选中非常规次要位置时，才在“次要位置”标签旁显示警告，并保留解释衰减规则的提示。
- 更改主位置后，继续使用现有规则选择默认次要位置并重新生成对应体型。

### 成长设定

- 成长设定位于球员身份右侧，桌面端目标宽度 350 px，并以 350 px 作为最大宽度，不占用剩余全部宽度。
- 新秀模式在同一行显示三个控件：巅峰综评约 120 px、即战力约 92 px、新秀综评约 112 px，间距约 7 px，控件高度约 34 px。
- 巅峰综评保留上下限输入，即战力保留独立随机按钮，新秀综评保持绿色只读结果样式。
- 即战力说明位于控件下方，以简短辅助文字解释数值越高越接近巅峰能力，不占用额外表单列。
- 巅峰模式使用同一块紧凑区域显示“巅峰值直出”和固定年龄 28，不为不存在的即战力或新秀综评预留空列。

### 身体设定

- 身体设定单独占一行，桌面端依次显示身高、体重、臂展、肩宽、颈长、躯干六个字段。
- 身高显示 `cm`，体重显示 `kg`；臂展、肩宽、颈长、躯干在数值后显示 `/100`，明确它们属于 1–100 体型量表。
- 随机身体按钮保留在区块标题右侧，只随机身体参数。
- 现有字段范围、数值提交方式和按位置生成身体参数的规则保持不变。

### 状态与操作底栏

- 设定区不再显示 `0/13` 完成进度和进度条。
- 左侧状态文字为“确认设定后开始抽取球队”，使用 12 px 加粗文字和状态圆点，保证它与表单辅助文字有明显层级差。
- 右侧依次显示“重置设定”和“确认并抽取”。两个按钮高 44 px；确认按钮更宽、使用主按钮样式，重置按钮保持次级样式。
- 窄屏下两个按钮共享整行，确认按钮仍拥有更高的宽度权重；状态文字单独占一行，避免与按钮挤压。

## 姓名数据流

- 组件内部将当前单一 `rookieName` 编辑状态拆为 `firstName` 和 `lastName`。
- `rookieNames.ts` 暴露独立的名、姓生成函数；完整姓名生成函数可继续作为组合入口，三者复用现有名字数组和随机选择逻辑。
- 确认设定时分别去除名、姓首尾空白并压缩内部连续空白。任一字段为空时，只为该字段生成随机值。
- 展示、结果导出和下载文件名继续使用按 `firstName + " " + lastName` 拼接的完整英文姓名，因此下游结果格式不变。
- 重置设定会同时重新生成名和姓，并继续重置现有的全部设定和生成进度。

## 确认态与重新编辑

- 用户点击“确认并抽取”后，设定面板折叠为单行紧凑摘要。新秀模式显示完整姓名、年龄、主/次位置、巅峰综评、即战力、身高和体重；巅峰模式不显示即战力，其余信息相同。
- 摘要提供“修改设定”操作。点击后返回编辑态，保留当前设定值，但停止正在进行的球队抽取，并清空已选球队、球员、属性锁定和完成进度；这是因为这些结果都依赖设定值。
- 返回编辑态后，用户可使用“重置设定”恢复默认值，或重新确认并开始抽取。
- 折叠摘要不重复显示生成进度，避免与球队球员区出现两个进度来源。

## 进度迁移

- `已完成数量 / 13` 和紧凑进度条移动到球队球员区头部，标签为“球员生成进度”。
- 未确认设定时显示 `0 / 13`，并保留“基础设定待确认”的状态说明。
- 每锁定一个属性组，数字和进度条立即更新；完成后显示 `13 / 13`。
- 现有球队名称、轮次、展示人数和换球员操作继续保留，进度信息与它们在同一头部内分区排列，不挤占球员卡片区域。

## 响应式行为

- 1024 px 及以上使用桌面布局：身份与最大 350 px 的成长区并排，六个身体字段同排，确认后显示横向摘要。
- 640–1023 px 保留四步向导；身份和成长区上下排列，位置组可并排，身体字段每行三项。
- 360–639 px 继续使用四步向导；名、姓和年龄保持同一行，使用 `minmax(0, 1fr) minmax(0, 1fr) 82px` 三列布局。
- 359 px 及以下将名和姓放在第一行两列，年龄放在第二行；不继续压缩文字或允许控件覆盖。
- 窄屏上的输入、随机按钮、位置段和主要操作保持至少 40 px 的可点击高度；确认和重置按钮保持 44 px。
- 所有状态均不得引发布局横向溢出或文字与相邻控件重叠。

## 可访问性

- 名、姓、年龄输入均有独立可读标签；随机按钮提供明确的 `aria-label` 和悬停提示，分别表述“随机名”“随机姓”。
- 主次位置继续使用带 `aria-label` 的分段按钮组，并用 `aria-pressed` 表达选中状态。
- 禁用的主位置次要选项同时使用原生 `disabled`，不能只依赖颜色表达。
- 非常规位置警告包含文字，不只使用颜色或图标。
- 数字输入在键盘提交、失焦提交和禁用状态下均保持可预测行为。
- 现有减少动态效果的偏好和焦点样式保持有效。

## 实现边界

- 主要修改 `src/components/RookieBuilder.tsx`、`src/rookieNames.ts` 和 `src/styles.css`。
- 沿用现有 React 状态、Tailwind 工具类、CSS 断点和 Lucide 图标，不新增依赖。
- 仅在重复布局或输入提交逻辑确实需要复用时提取小型局部组件，不进行与本需求无关的 `RookieBuilder` 重构。

## 验证与验收

实现完成后至少验证以下内容：

1. TypeScript 与 Vite 生产构建成功。
2. 名和姓可以分别编辑、分别随机，任一随机操作不改变另一字段或即战力。
3. 年龄只会提交 18–23 的整数；巅峰模式固定显示 28。
4. 主位置无法作为次要位置；非常规警告只在选中非常规组合时出现。
5. 姓名、年龄、位置、成长和身体设定在确认后正确进入结果计算、展示、复制与下载内容。
6. 确认后设定区折叠；“修改设定”保留设定值并清除依赖它的抽取及锁定进度。
7. 生成进度只在球队球员区显示，并从 `0 / 13` 正确更新至 `13 / 13`。
8. 在至少 1440、1024、768、390 px 宽度下进行浏览器截图检查，确认无横向溢出、控件拉伸、文字遮挡或不合理空白。
9. 用键盘完成姓名、年龄、位置和确认操作，检查焦点可见性、标签和禁用状态。
